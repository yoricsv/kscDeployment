# Автономные пакеты установки для узлов вне домена

Узлы вне домена нельзя охватить групповой политикой и удалённой установкой
с доменной аутентификацией. Для них создаётся **автономный пакет установки** —
самораспаковывающийся файл, в который уже встроены адрес Сервера
администрирования и сертификат, поэтому установка не требует ручного ввода
параметров и не зависит от домена.

## 1. Создание пакета в консоли KSC

1. **Обнаружение устройств и развёртывание → Развёртывание и назначение →
   Инсталляционные пакеты**.
2. Выберите пакет «Агент администрирования Kaspersky Security Center»
   (для Linux — «Kaspersky Endpoint Security для Linux» отдельным пакетом).
3. Кнопка **Развернуть → Создать автономный пакет установки**.
4. В параметрах пакета обязательно задайте:

   | Параметр | Значение | Почему |
   |---|---|---|
   | Адрес Сервера | `ksc.domain.local` | В сертификате Сервера указано имя, а не адрес: при подключении по IP проверка сертификата не проходит |
   | Порт | `13000`, SSL включён | Соответствует правилам межсетевого экрана Сервера |
   | Не устанавливать, если уже установлен | включено | Исключает повторную установку при повторном запуске |
   | Пароль удаления Агента | задать | На узлах вне домена нет доменного администратора, пароль защищает Агент от удаления пользователем |
   | Перемещать в группу | `Вне домена` | Для таких узлов действует отдельная политика |

5. После создания пакет доступен по адресу
   `http://ksc.domain.local:8060/pkginst/<имя>.exe` (Windows) или `.sh` (Linux).

## 2. Доставка на узел

В аттестованном контуре доставка выполняется одним из способов:

- скачивание с веб-сервера KSC по адресу выше (порт 8060 разрешён для всей
  подсети — см. правила межсетевого экрана Сервера);
- копирование через учтённый съёмный носитель с регистрацией в журнале
  учёта машинных носителей.

Передача пакета за пределы аттестованного контура не допускается: пакет
содержит сертификат Сервера администрирования.

## 3. Установка

**Windows:** запуск от имени администратора, установка выполняется без
диалогов. Проверка:

```powershell
Get-Service klnagent
& "C:\Program Files (x86)\Kaspersky Lab\NetworkAgent\klnagchk.exe" -sendhb -nowait
```

Если имя `ksc.domain.local` не разрешается (узел не использует DNS домена),
добавьте запись в `C:\Windows\System32\drivers\etc\hosts`:

```
10.20.30.20    ksc.domain.local    ksc
```

**Linux:** пакет `.sh` запускается с правами root, далее — проверка
сценарием `hosts/linux-debian/30_test-agent.sh`.

## 4. Особенности эксплуатации узлов вне домена

| Особенность | Следствие | Мера |
|---|---|---|
| Нет доменной аутентификации | Удалённая установка push-методом невозможна | Только автономный пакет, установка локально |
| Нет опроса Active Directory | Узел не появится автоматически в списке устройств | Ведение перечня `inventory.csv`, IP-опрос подсети в KSC |
| Нет доменных политик Windows | Харденинг не применяется через GPO | Локальный запуск `hosts/win-endpoint/hardening/Invoke-Hardening.ps1` |
| Нет централизованной смены паролей | Локальные учётные записи выходят из-под контроля | Отдельный регламент смены паролей, фиксация в журнале |

## 5. Контроль охвата

Ежемесячно сверяйте:

1. перечень `hosts/standalone/inventory.csv`;
2. список устройств в KSC (группа «Вне домена»);
3. результаты IP-опроса подсети `10.20.30.0/24` в KSC.

Узел, найденный опросом, но отсутствующий в перечне, — незарегистрированное
устройство: подлежит разбирательству в соответствии с регламентом
обеспечения кибербезопасности.
