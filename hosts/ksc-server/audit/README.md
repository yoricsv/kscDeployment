# Аудит узла KSC: ОС, СУБД, прикладное ПО

Комплект настройки регистрации событий на сервере администрирования и их
доставки в MaxPatrol 10 Collector. Требования Приказа ОАЦ РБ № 130 приняты
за минимум; состав расширен событиями, необходимыми для реагирования на
инциденты и их расследования.

## Порядок выполнения

| № | Сценарий | Что делает |
|---|----------|------------|
| 1 | `00_Set-OsAudit.ps1` | Расширенная политика аудита ОС (подкатегории задаются по GUID, не зависят от языка сборки), командная строка в событиях 4688, журналирование PowerShell с транскрипцией, размеры и включение каналов, SACL на каталоги KSC/СУБД/резервных копий и ветку реестра KasperskyLab |
| 2 | `10_Enable-DbAudit.ps1` | Плагин `server_audit` MariaDB: каталог аудита с ограниченными правами, блок параметров в `my.ini` из `11_server_audit.ini.template`, перезапуск службы, проверка переменных |
| 3 | `20_Install-AuditForwarder.ps1` | Журнал Windows «MariaDB-Audit», размещение конвертера `21_Publish-DbAuditToEventLog.ps1`, задача планировщика `KSC-DbAudit-Forwarder` |
| 4 | `30_Set-KscAppAudit.ps1` | Аудит ПО KSC: размеры журналов Kaspersky, доступ учётной записи сбора, SACL на каталог установки, чек-лист параметров консоли (экспорт в SIEM, сроки хранения, роль аудитора) |
| 5 | `40_Set-AuditCollectorAccess.ps1` | УЗ `kscaudit`, членство в группах доступа, права на журнал и WMI, правила брандмауэра только для адреса коллектора |
| 6 | `12_Set-Mp10MariaDbAccess.ps1` | Отдельная настройка MariaDB для профиля MaxPatrol VM `MySQL Audit`: read-only УЗ, удалённый доступ и TCP/3306 только от коллектора |
| 7 | `90_Test-Audit.ps1` | Сквозная проверка ОС, СУБД, ПО и доставки; таблица результатов и код возврата |

Откат: `10_Enable-DbAudit.ps1 -Rollback`, `20_Install-AuditForwarder.ps1 -Rollback`,
`40_Set-AuditCollectorAccess.ps1 -Rollback`. Изменяющие сценарии `00_`, `10_`,
`12_`, `20_`, `30_` и `40_` поддерживают `-WhatIf` — выполните пробный прогон до
применения. Сценарии `21_` и `90_` не изменяют конфигурацию: первый работает как
конвертер событий, второй выполняет проверки.

`12_Set-Mp10MariaDbAccess.ps1` относится к отдельному сценарию MaxPatrol VM
из документации PT и не заменяет Windows Event Log forwarder для SIEM.

## Источники событий

| Источник | Канал | Доставка в MP 10 |
|----------|-------|------------------|
| ОС | Security, System, PowerShell/Operational, TaskScheduler, WinRM, брандмауэр, RDP, SMB | удалённое чтение журналов Windows |
| СУБД MariaDB | `server_audit.log` → журнал «MariaDB-Audit» | удалённое чтение журнала Windows |
| KSC | база событий Сервера; «Kaspersky Event Log» | экспорт в SIEM по Syslog/CEF и/или чтение журнала Windows |

Параметры — в `common/config.ps1` (секции «Аудит ОС и прикладного ПО»,
«Аудит СУБД»). Соответствие перечню событий и настройка источника в MaxPatrol
описаны в [docs/02_admin_guide/audit_mp10.md](../../../docs/02_admin_guide/audit_mp10.md).

## Замечания

- На узле в домене состав аудита закрепляется групповой политикой: локальные
  значения перезаписываются при очередном обновлении политики.
- Плагин `server_audit` на Windows пишет только в файл (MDEV-19851: значение
  `SYSLOG` на этой платформе не действует) — отсюда промежуточный конвертер.
- Транскрипты PowerShell содержат вывод команд администратора; каталог
  `C:\ProgramData\KscDeployment\pstranscripts` доступен только SYSTEM
  и администраторам.
