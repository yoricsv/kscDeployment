# Узлы Debian

Групповая политика к узлам Debian неприменима, средства управления
конфигурацией не используются — установка выполняется сценариями этого
каталога локально на каждом узле.

## Порядок

```bash
sudo ./00_prepare-host.sh                                   # проверки предпосылок
sudo ./10_install-netagent.sh /path/klnagent64_<ver>_amd64.deb
sudo ./20_install-kesl.sh /path/kesl_<ver>_amd64.deb
sudo ./30_test-agent.sh                                     # приёмочная проверка
sudo ./hardening/harden.sh --check                          # затем --apply
```

Порядок обязателен: Kaspersky Endpoint Security для Linux без Агента
администрирования не получит политику и лицензию от Сервера и останется
с параметрами по умолчанию.

## Параметры

Все сценарии читают `common.sh`. Значения должны совпадать с
`common/config.ps1`. Переопределение на время запуска возможно через
переменные окружения:

```bash
sudo KSC_FQDN=ksc.example.local KSC_IP=10.20.30.20 ./10_install-netagent.sh /path/pkg.deb
```

## Что проверить до установки

| Проверка | Почему |
|---|---|
| Версия ядра в перечне поддерживаемых KESL | Перечень ограничен; на неподдерживаемом ядре постоянная защита файлов не запустится |
| Имя Сервера разрешается | В сертификате Сервера указано имя; подключение по адресу приводит к ошибке проверки сертификата |
| Расхождение времени с контроллером домена менее 5 минут | Нарушается проверка сертификата |
| Отсутствие другого средства антивирусной защиты | Одновременная работа двух средств приводит к отказу обоих |
| Доступность локального зеркала пакетов | Внешние репозитории в контуре недоступны, а установка может потребовать зависимостей |

## Узлы вне домена

Дополнительно требуется:

1. запись в `/etc/hosts` с именем и адресом Сервера — служба имён домена
   таким узлам недоступна;
2. учёт узла в `hosts/standalone/inventory.csv` — опрос службы каталогов
   его не обнаружит;
3. пароль защиты Агента от удаления — доменного администратора,
   ограничивающего локальные права, на таком узле нет.

## Откат харденинга

`harden.sh` сохраняет исходные файлы с суффиксом `.ksc-bak-<дата>`.
Восстановление конфигурации SSH:

```bash
sudo cp /etc/ssh/sshd_config.ksc-bak-<дата> /etc/ssh/sshd_config
sudo sshd -t && sudo systemctl reload ssh
```

Правила межсетевого экрана и параметры ядра восстанавливаются удалением
`/etc/sysctl.d/99-ksc-hardening.conf`, `/etc/audit/rules.d/99-ksc.rules`
и повторной настройкой `ufw`.
