# Сценарии по типам узлов

| Каталог | Узел | Что содержит |
|---|---|---|
| `ksc-server/` | Сервер администрирования `ksc` `10.20.30.20` | Подготовка, разметка дисков, межсетевой экран, MariaDB, установка Сервера и Web Console, настройка после установки, резервное копирование, приёмочная проверка, харденинг |
| `dc-gpo/` | Контроллеры домена `10.20.30.10`, `.11` | Служебные учётные записи и группы, политика установки Агента, контроль охвата, проверка защищённости контроллера домена |
| `rds-mgmt/` | АРМ администратора `10.20.30.15` | Подготовка точки управления, харденинг привилегированного узла |
| `win-endpoint/` | Узлы Windows | Установка Агента вручную, харденинг рабочей станции |
| `linux-debian/` | Узлы Debian | Подготовка, Агент, KESL, приёмочная проверка, харденинг |
| `standalone/` | Узлы вне домена | Порядок создания и применения автономных пакетов, перечень узлов |

## Общие правила

1. **Единый источник параметров.** Сценарии не содержат адресов и портов:
   значения читаются из `common/config.ps1` (Windows) и
   `hosts/linux-debian/common.sh` (Debian). Изменения вносятся только туда.

2. **Предварительный просмотр.** Перед применением изменений запускайте
   сценарий с `-WhatIf` (PowerShell) либо `--check` (Bash).

3. **Порядок нумерации.** Префикс имени файла задаёт порядок выполнения:
   `00` — подготовка, `10`–`30` — установка, `40`–`50` — настройка и
   обслуживание, `60` — приёмка.

4. **Повторный запуск.** Сценарии рассчитаны на повторное выполнение:
   уже выполненные действия пропускаются, а не дублируются.

5. **Различие в области действия правил.** Правила для портов управления
   создаются по перечню адресов, для служебных портов Агентов — для всего
   сегмента. Расширять область действия правил управления без согласования
   не допускается.
