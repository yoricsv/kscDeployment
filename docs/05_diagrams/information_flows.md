# Таблицы информационных потоков

Документ описывает все информационные потоки системы антивирусной защиты
в аттестованном сегменте `10.20.30.0/24`. Идентификаторы потоков (`F1`…`F13`)
соответствуют обозначениям на логической схеме `logical.drawio`.

Условные обозначения направления:
`→` — односторонний поток, `↔` — двустороннее взаимодействие в рамках
одного соединения.

---

## 1. Потоки управления системой

Потоки этой группы разрешены **только с ограниченного перечня адресов**.
Подключение с иных адресов блокируется межсетевым экраном Сервера и
регистрируется как событие безопасности.

| № | Источник | Назначение | Протокол / порт | Напр. | Содержание | Ограничение доступа | Защита |
|---|---|---|---|---|---|---|---|
| F1 | АРМ администратора `10.20.30.15` | Сервер `ksc` `10.20.30.20` | TCP 13291 (MMC) | ↔ | Команды управления, параметры политик и задач, сведения о состоянии узлов | Только `10.20.30.15` | Собственный протокол KSC поверх TLS, аутентификация доменной учётной записью |
| F1 | АРМ администратора | Сервер `ksc` | TCP 13299 (OpenAPI) | ↔ | Обращения Web Console к Серверу | Только `10.20.30.15` и согласованные адреса смежных СЗИ | TLS |
| F1 | АРМ администратора | Сервер `ksc` | TCP 8080 (Web Console) | ↔ | Веб-интерфейс управления | Только `10.20.30.15` | HTTPS, сертификат корпоративного УЦ |
| F2 | АРМ администратора | Сервер `ksc` | TCP 3389 (RDP) | ↔ | Администрирование операционной системы Сервера | Только `10.20.30.15` | TLS, проверка подлинности на уровне сети, запрет проброса буфера обмена и дисков |
| F2 | АРМ администратора | Сервер `ksc` | TCP 5985 (WinRM) | ↔ | Выполнение сценариев обслуживания | Только `10.20.30.15` | Kerberos, шифрование сообщений |
| F3 | Смежные СЗИ `<уточняется>` | Сервер `ksc` | По согласованию (SNMP 161/UDP, WinRM 5985/TCP, OpenAPI 13299/TCP) | ↔ | Контроль состояния Сервера, получение сведений о защите | Только адреса из перечня `SecurityToolsHosts` | Согласно применяемому средству |

**Существенное условие.** Перечень адресов, которым разрешено управление,
задаётся единственным параметром `SecurityToolsHosts` в `common/config.ps1`.
Правила межсетевого экрана формируются из него сценарием
`hosts/ksc-server/10_Set-Firewall.ps1`. Изменение перечня иным способом
приводит к расхождению фактического состояния с документированным.

## 2. Потоки взаимодействия с защищаемыми узлами

Потоки этой группы разрешены **для всего сегмента** `10.20.30.0/24`.
Ограничение по перечню адресов здесь неприменимо: узлы добавляются и
изменяются, а без этих потоков узел не сможет сообщать о своём состоянии,
то есть окажется вне контроля системы защиты.

| № | Источник | Назначение | Протокол / порт | Напр. | Содержание | Ограничение доступа | Защита |
|---|---|---|---|---|---|---|---|
| F5 | Агент на узле | Сервер `ksc` | TCP 13000 | → | Сведения о состоянии узла, события защиты, результаты задач, инвентаризация | Сегмент `10.20.30.0/24` | SSL, взаимная проверка по сертификату Сервера |
| F5 | Агент на узле | Сервер `ksc` | TCP 14000 | → | То же, соединение без SSL | Сегмент `10.20.30.0/24`; применяется только при невозможности SSL | Отсутствует — использование подлежит обоснованию |
| F6 | Сервер `ksc` | Агент на узле | UDP 15000 | → | Команда немедленной синхронизации («пробуждение» Агента) | Сегмент `10.20.30.0/24` | Проверка подлинности отправителя Агентом |
| F6 | Сервер `ksc` | Агент на узле | UDP 13000 | → | Широковещательное обнаружение | Сегмент `10.20.30.0/24` | — |
| F6 | Сервер `ksc` | Агент на узле | TCP 13000 (в рамках установленного соединения) | → | Политики, задачи, обновления антивирусных баз, пакеты установки | Сегмент `10.20.30.0/24` | SSL |
| F7 | Узел вне домена | Сервер `ksc` | TCP 8060 / 8061 | ↔ | Загрузка автономного пакета установки Агента | Сегмент `10.20.30.0/24` | HTTP / HTTPS; пакет содержит сертификат Сервера, вынос за пределы контура не допускается |
| F13 | Сервер `ksc` | Узел Windows | TCP 445, TCP 135 | → | Удалённая установка Агента средствами Сервера | Инициируется только Сервером `10.20.30.20`; на узле правило создаётся точечно | Подпись SMB, учётная запись `svc_ksc_deploy` |

Периодичность потока F5 — по умолчанию каждые 15 минут; событие критической
важности передаётся немедленно.

## 3. Потоки взаимодействия со службой каталогов

| № | Источник | Назначение | Протокол / порт | Напр. | Содержание | Ограничение доступа | Защита |
|---|---|---|---|---|---|---|---|
| F8 | Сервер `ksc` | Контроллеры домена `10.20.30.10`, `.11` | TCP 389 (LDAP) | ↔ | Опрос службы каталогов: перечень компьютеров, подразделений, групп; интервал 1 час | Инициируется Сервером | Подпись LDAP; при внедрении LDAPS — TCP 636 |
| F8 | Сервер `ksc` | Контроллеры домена | TCP/UDP 88 (Kerberos), TCP/UDP 53 (DNS) | ↔ | Аутентификация служебных учётных записей, разрешение имён | Инициируется Сервером | Kerberos (AES) |
| F9 | Контроллер домена | Сервер `ksc`, ресурс `KLSHARE` | TCP 445 (SMB) | → | Получение пакета установки Агента при применении групповой политики | Инициируется узлом при применении политики | Подпись SMB; на ресурс выданы права только на чтение |
| F10 | Контроллер домена | Узлы Windows в домене | TCP 445 (SYSVOL) | → | Применение групповой политики установки Агента при загрузке узла | Подразделения по перечню; **подразделение контроллеров домена исключено** | Подпись SMB |

**Существенное условие.** Групповая политика установки Агента не
привязывается к подразделению контроллеров домена: отказ контроллера
домена приводит к отказу аутентификации во всей сети, поэтому установка
на такие узлы выполняется отдельно, в согласованное окно.

## 5. Потоки передачи сведений смежным средствам защиты

| № | Источник | Назначение | Протокол / порт | Напр. | Содержание | Ограничение доступа | Защита |
|---|---|---|---|---|---|---|---|
| F4 | Сервер `ksc` | Система мониторинга событий `<уточняется>` | TCP 514 (syslog), формат CEF | → | События критической и предупреждающей важности | Единственный адрес получателя, задан параметром `SiemHost` | При поддержке получателем — TLS; иначе поток замыкается в пределах аттестованного сегмента |

Передаются не все события: избыточный поток затрудняет выявление значимых
событий на стороне получателя и увеличивает нагрузку. Перечень
передаваемых типов событий согласуется с администратором безопасности.

## 6. Потоки, отсутствующие в системе

Перечень приведён для полноты: отсутствие этих потоков — проектное решение,
а их появление означает изменение условий функционирования и требует
согласования.

| Поток | Состояние | Обоснование |
|---|---|---|
| Обращения к серверам обновлений производителя в сети общего пользования | Отсутствует | Изолированный контур; обновления доставляются контролируемо на съёмных носителях либо через шлюз по отдельному регламенту |
| Участие в облачной службе репутации (KSN) | Отключено | Передача сведений за пределы аттестованного контура не допускается |
| Сетевой доступ к СУБД Сервера | Заблокирован | СУБД размещена на том же узле; сетевой интерфейс не используется |
| Управление узлами средствами Ansible и аналогичными | Отсутствует | Средства управления конфигурацией не применяются; появление такого канала требует внесения в модель угроз |
| Доступ пользователей к консоли управления | Отсутствует | Управление доступно только с АРМ администратора членам групп ролей |

## 8. Порядок актуализации

Таблицы подлежат пересмотру при:

- изменении перечня адресов, которым разрешено управление;
- подключении нового смежного средства защиты;
- изменении состава защищаемых узлов, влияющем на схему взаимодействия;
- переходе к применению средств управления конфигурацией;
- изменении версии Сервера администрирования, если изменился перечень портов.

Соответствие фактических правил межсетевого экрана настоящим таблицам
проверяется ежемесячно сценарием `hosts/ksc-server/60_Test-Deployment.ps1`.
