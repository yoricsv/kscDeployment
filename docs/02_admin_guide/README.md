# Руководство администратора системы антивирусной защиты

**Версия документа:** 1.0
**Адресовано:** администраторам, входящим в группу `<домен>\KSC-Admins`

---

## 1. Общие положения

### 1.1. Область применения

Руководство определяет порядок развёртывания, настройки и эксплуатации
Сервера администрирования Kaspersky Security Center и подчинённых ему
средств защиты узлов.

### 1.2. Условия допуска к работе

К работе допускается администратор, который:

- включён в группу `<домен>\KSC-Admins`;
- ознакомлен с настоящим руководством и регламентом обеспечения
  кибербезопасности (`docs/04_security_policy`);
- работает **только с АРМ администратора** `10.20.30.15`.

Подключение к Серверу администрирования с иных узлов заблокировано
правилами межсетевого экрана. Попытка подключения с иного адреса
регистрируется как событие безопасности и подлежит разбирательству.

### 1.3. Правила обращения с параметрами доступа

- Пароли не сохраняются в файлах репозитория и в сценариях: сценарии
  запрашивают их при выполнении.
- Пароли служебных учётных записей и учётной записи СУБД хранятся в
  порядке, установленном регламентом, вне репозитория.
- Передача параметров доступа по электронной почте и в средствах обмена
  сообщениями не допускается.

## 2. Порядок развёртывания

Развёртывание выполняется в указанной последовательности. Каждый этап
завершается проверкой; переход к следующему этапу без успешной проверки
не допускается.

### Этап 1. Подготовка Сервера

```powershell
# Выполняется на узле ksc от имени администратора домена
cd C:\deploy\kscDeployment\hosts\ksc-server
.\00_Prepare-Host.ps1
```

Сценарий проверяет версию операционной системы, объём ресурсов, статическую
адресацию, записи службы имён (прямую и обратную), членство в домене,
создаёт каталоги и исключения средства защиты, настраивает синхронизацию
времени.

**Записи службы имён проверяются обязательно.** В сертификат Сервера
записывается его полное имя; при отсутствии или несоответствии записи
Агенты не смогут установить доверенное соединение.

Если тома `D:` и `E:` отсутствуют, выполните разметку:

```powershell
.\01_New-DiskLayout.ps1 -Mode NewDisks          # если диски добавлены в системе виртуализации
.\01_New-DiskLayout.ps1 -Mode ShrinkC -SystemSizeGB 120 -DbSizeGB 150   # разделение единственного диска
```

Режим `ShrinkC` изменяет разметку существующего диска и требует
подтверждения. Перед выполнением создайте снимок состояния виртуальной
машины.

### Этап 2. Правила межсетевого экрана

```powershell
.\10_Set-Firewall.ps1
```

Сценарий устанавливает запрет входящих подключений по умолчанию и создаёт
правила согласно таблице информационных потоков. Отмена изменений —
`.\10_Set-Firewall.ps1 -Rollback`.

Перед выполнением внесите адреса смежных средств защиты в
`common/config.ps1`, параметр `SecurityToolsHosts`. Если перечень пуст,
доступ будет разрешён только с АРМ администратора.

### Этап 3. Установка СУБД

```powershell
.\20_Install-MariaDB.ps1 -MsiPath D:\distr\mariadb-10.11.x-winx64.msi
```

Сценарий устанавливает СУБД, применяет конфигурацию из
`21_my.ini.template`, создаёт базу данных и учётную запись согласно
`22_Create-Database.sql`.

Существенные параметры конфигурации и их назначение:

| Параметр | Значение | Назначение |
|---|---|---|
| `bind-address` | `127.0.0.1` | СУБД доступна только с самого узла: сетевой доступ к базе данных исключён |
| `innodb_buffer_pool_size` | `6G` | Около 40 % оперативной памяти; остаток необходим Серверу администрирования |
| `innodb_log_file_size` | `1G` | Задаётся **до первого запуска**: изменение после запуска требует удаления файлов журнала |
| `innodb_flush_log_at_trx_commit` | `0` | Повышает производительность ценой возможной потери последних записей при аварийном отключении питания; для событий антивирусной защиты приемлемо |
| `max_allowed_packet` | `32M` | Меньшее значение приводит к отказу установки Сервера |

Проверка после установки:

```powershell
& 'C:\Program Files\MariaDB 10.11\bin\mysql.exe' -u kscadmin -p -e "SHOW VARIABLES LIKE 'innodb_buffer_pool_size'; SHOW DATABASES;"
```

**Совместимость версии СУБД с версией Сервера администрирования подлежит
проверке по документации применяемого выпуска до начала установки.**

### Этап 4. Установка Сервера администрирования

```powershell
.\30_Install-KscServer.ps1 -ChecksOnly      # только проверки
.\30_Install-KscServer.ps1 -SetupPath D:\distr\ksc\setup.exe
```

Значения, вводимые в мастере установки:

| Параметр мастера | Значение |
|---|---|
| Тип установки | Выборочная |
| Размер сети | от 1000 до 5000 узлов |
| Учётная запись службы | `<домен>\svc_ksc` |
| Тип СУБД | MySQL / MariaDB |
| Адрес СУБД | `localhost`, порт 3306 |
| Имя базы данных | `ksc` |
| Учётная запись СУБД | `kscadmin` |
| Общий ресурс | `E:\KLSHARE` |
| Адрес Сервера | полное имя `ksc.<домен>` — **не адрес** |
| Порты | значения по умолчанию |

Выбор размера сети «от 1000 до 5000» при фактических 254 узлах сделан
намеренно: этот параметр определяет предустановленные значения задач и
интервалов, изменить его после установки нельзя, а запас исключает
переустановку при расширении.

### Этап 5. Web Console

```powershell
.\35_Install-WebConsole.ps1
```

Адрес Сервера — `ksc.<домен>:13299`, порт консоли — 8080.

После установки замените самоподписанный сертификат на выданный
корпоративным удостоверяющим центром: **Параметры → Web Console →
Сертификат**. До замены браузер будет сообщать о недоверенном соединении,
что затрудняет выявление подмены.

### Этап 6. Настройка после установки

```powershell
.\40_Set-PostInstall.ps1
```

Сценарий ведёт по перечню обязательных настроек, фиксируя их выполнение.
Состояние сохраняется в `C:\ProgramData\KscDeployment\postinstall-state.json`,
поэтому работу можно прервать и продолжить.

Обязательные настройки:

1. **Хранение событий — 365 суток.** Свойства Сервера → Хранилище событий.
   Задайте одновременно срок 365 суток и предельное число событий
   20 000 000. Через месяц эксплуатации сверьте фактический темп поступления
   событий и скорректируйте предел, если годовой объём его превышает.
2. **Хранение отчётов — 365 суток.**
3. **Роли.** Пользователи и роли: группе `KSC-Admins` — «Главный
   администратор», `KSC-Operators` — «Оператор», `KSC-Auditors` — «Аудитор».
4. **Опрос службы каталогов** — включить, интервал 1 час.
5. **Опрос диапазона адресов** `10.20.30.0/24` — включить. Необходим для
   выявления узлов вне домена, включая незарегистрированные.
6. **Группы устройств:** `Серверы`, `АРМ`, `Linux`, `Вне домена`.
   Правила перемещения: по подразделению службы каталогов, по типу
   операционной системы, по отсутствию членства в домене.
7. **Задачи:** загрузка обновлений в хранилище (каждые 2 часа), обслуживание
   Сервера (еженедельно), резервное копирование (ежедневно), поиск
   уязвимостей (еженедельно).
8. **Уведомления** — адрес получателя, события критической важности.
9. **Передача событий в систему мониторинга** — syslog, формат CEF.
10. **Лицензирование** — добавить ключ, включить автоматическое
    распространение.
11. **Резервная копия сертификата Сервера** — сохранить отдельно.

### Этап 7. Резервное копирование

```powershell
.\50_Backup-KscServer.ps1 -Register -Time 01:30
```

Регистрирует ежедневное задание. Копии размещаются на томе `E:`,
хранится 30 копий. Вынос на сетевой ресурс:

```powershell
.\50_Backup-KscServer.ps1 -RemotePath \\backup\ksc$
```

### Этап 8. Защищённость Сервера

```powershell
.\hardening\Invoke-Hardening.ps1 -WhatIf     # предварительный просмотр
.\hardening\Invoke-Hardening.ps1
```

Изменения реестра сохраняются в файл отката
`C:\ProgramData\KscDeployment\rollback\rollback-<дата>.json`. Отмена:

```powershell
..\..\common\Restore-Baseline.ps1 -RollbackFile <путь>
```

Часть параметров (криптографические протоколы, SMBv1, защита процесса LSA)
применяется после перезагрузки.

### Этап 9. Приёмочная проверка

```powershell
.\60_Test-Deployment.ps1
```

Формирует отчёт в текстовом виде и таблицу. Отчёт прикладывается к акту
ввода в эксплуатацию.

## 3. Развёртывание Агентов на защищаемых узлах

### 3.1. Узлы Windows в домене — групповая политика

Подготовка объектов службы каталогов (выполняется на контроллере домена):

```powershell
cd C:\deploy\kscDeployment\hosts\dc-gpo
.\00_New-KscAccounts.ps1
```

Создание политики установки:

```powershell
.\10_New-AgentGpo.ps1 -VerifyOnly            # проверка предпосылок
.\10_New-AgentGpo.ps1 `
  -MsiUncPath '\\ksc.<домен>\KLSHARE\Packages\NetAgent\klnagent64.msi' `
  -TargetOu 'OU=Workstations,DC=<домен>,DC=local'
```

**Политика не связывается с подразделением контроллеров домена.**
Установка на контроллер домена выполняется отдельно, в согласованное окно,
после проверки на резервном узле: отказ контроллера домена приводит к отказу
аутентификации во всей сети.

Порядок ввода политики в действие:

1. Ограничьте применение политики фильтром безопасности — 2–3 узла.
2. Убедитесь в успешной установке (`gpresult /r`, наличие службы `klnagent`,
   появление узла в консоли).
3. Расширьте фильтр на подразделение целиком.

Установка применяется при следующей загрузке узла.

### 3.2. Узлы Windows — установка вручную

Применяется, если узел долго не перезагружался, установка политикой не
выполнилась либо узел вне домена:

```powershell
cd C:\deploy\kscDeployment\hosts\win-endpoint
.\00_Install-NetworkAgent.ps1
```

### 3.3. Узлы Debian

```bash
sudo ./00_prepare-host.sh
sudo ./10_install-netagent.sh /path/klnagent64_<ver>_amd64.deb
sudo ./20_install-kesl.sh /path/kesl_<ver>_amd64.deb
sudo ./30_test-agent.sh
sudo ./hardening/harden.sh --check     # затем --apply
```

Порядок обязателен: без Агента приложение защиты не получит политику и
лицензию.

Перед установкой Kaspersky Endpoint Security для Linux сверьте версию ядра
с перечнем поддерживаемых: перечень ограничен, и на неподдерживаемом ядре
постоянная защита файлов не запустится.

### 3.4. Узлы вне домена

Порядок описан в `hosts/standalone/00_New-StandalonePackage.md`.
Перечень таких узлов ведётся в `hosts/standalone/inventory.csv` вручную:
опрос службы каталогов их не обнаруживает.

### 3.5. Контроль охвата

```powershell
cd C:\deploy\kscDeployment\hosts\dc-gpo
.\20_Test-AgentDeployment.ps1
```

Сопоставляет учётные записи компьютеров службы каталогов с фактическим
наличием Агента. Узлы, для которых установка не предусмотрена, вносятся
в `exclusions.txt` с обоснованием.

Полный контроль охвата складывается из трёх источников: отчёт по домену,
перечень узлов вне домена, результаты опроса диапазона адресов в консоли.

## 5. Устранение неисправностей

### 5.1. Установка Сервера прерывается на создании базы данных

Причины по частоте:

1. Не задан `max_allowed_packet=32M` в конфигурации СУБД.
2. Учётной записи `kscadmin` не выдано право `SELECT` на `mysql.*` —
   оно требуется установщику для проверки версии.
3. `innodb_buffer_pool_size` превышает доступную память, служба не запускается.

Проверка:

```powershell
& 'C:\Program Files\MariaDB 10.11\bin\mysql.exe' -u root -p -e "SHOW VARIABLES LIKE 'max_allowed_packet'; SHOW GRANTS FOR 'kscadmin'@'localhost';"
```

### 5.2. Агент не подключается к Серверу

| Признак | Причина | Действие |
|---|---|---|
| `klnagchk` сообщает об ошибке разрешения имени | Имя Сервера не разрешается | Проверить службу имён; для узлов вне домена — запись в файле `hosts` |
| Соединение отвергнуто | Порт 13000/TCP закрыт | Проверить правила межсетевого экрана Сервера |
| Ошибка проверки сертификата | Подключение выполняется по адресу, а не по имени, либо сертификат перевыпущен | Указать полное имя; при смене имени применить `klsetsrvcert` и `klmover` |
| Узел не появляется в консоли, служба запущена | Узел не отнесён ни к одной группе | Проверить раздел «Нераспределённые устройства» и правила перемещения |

### 5.3. Рост базы данных сверх ожидаемого

1. Определите преобладающий тип событий: Консоль → События, группировка
   по типу.
2. Отключите регистрацию малозначимых типов в политике.
3. Убедитесь, что заданы **оба** ограничения хранилища — срок и число
   событий.
4. Выполните задачу обслуживания Сервера.

Уменьшать срок хранения ниже 365 суток не допускается: срок установлен
требованием к системе. При недостаточности объёма увеличивается том `D:`.

### 5.4. Утрата Сервера администрирования

1. Разверните операционную систему и СУБД по этапам 1–3.
2. Восстановите данные: `klbackup.exe` в режиме восстановления.
3. Убедитесь, что восстановлен **сертификат Сервера** — иначе Агенты не
   восстановят доверие и потребуется ручное переподключение каждого узла
   средствами `klmover`.
4. Проверьте подключение узлов в течение 24 часов после восстановления.

### 5.5. Доступ к управлению утрачен

Если АРМ администратора недоступен, доступ к Серверу заблокирован правилами
межсетевого экрана. Порядок восстановления:

1. Подключение к консоли виртуальной машины через систему виртуализации
   (`10.20.30.11`) — этот путь не зависит от сетевых правил.
2. Временное добавление адреса нового АРМ в `common/config.ps1`
   (`RdsHost` либо `SecurityToolsHosts`) и повторное выполнение
   `10_Set-Firewall.ps1`.
3. Изменение согласуется с администратором безопасности и фиксируется
   в журнале.
