# Аудит узла KSC (ОС, СУБД, ПО) и передача событий в MaxPatrol 10

**Область применения:** узел KSC и СУБД `10.20.30.75` (Windows Server 2022),
коллектор MaxPatrol 10 `10.20.30.73`.
**Нормативное основание:** Приказ ОАЦ при Президенте Республики Беларусь № 130,
перечень типов и записей событий информационной безопасности. Перечень приказа
рассматривается как минимум: состав расширен событиями, без которых невозможно
восстановить картину инцидента (создание процессов, PowerShell, доступ к файлам).

---

## 1. Схема решения

Три источника событий узла доставляются на один коллектор:

```text
ОС Windows              -> Security, System, PowerShell/Operational, TaskScheduler,
                           WinRM, брандмауэр, RDP, SMB
СУБД MariaDB           -> server_audit.log -> конвертер -> журнал «MariaDB-Audit»
ПО Kaspersky (KSC)      -> база событий Сервера (экспорт Syslog/CEF),
                           журнал «Kaspersky Event Log»
        v  удалённое чтение журналов по RPC/WMI под УЗ kscaudit (Event Log Readers)
           + экспорт событий KSC по Syslog
MP 10 Collector 10.20.30.73
```

Цепочка аудита СУБД:

```text
MariaDB (плагин server_audit)
        v  запись в файл D:\MariaDB\audit\server_audit.log (ротация 100 МБ x 20)
Конвертер 21_Publish-DbAuditToEventLog.ps1 (задача планировщика, запуск от SYSTEM)
        v  запись событий
Журнал Windows «MariaDB-Audit» (источник «MariaDB-ServerAudit», буфер 1 ГБ)
        v  удалённое чтение по RPC/WMI под УЗ kscaudit (Event Log Readers)
MP 10 Collector 10.20.30.73
```

Прямой вывод в syslog не применяется: на платформе Windows плагин `server_audit`
поддерживает только вывод в файл, значение `server_audit_output_type=SYSLOG` там
не действует (MDEV-19851). Порт СУБД 3306 коллектору не открывается — сбор
выполняется из журнала событий ОС, что сохраняет действующее ограничение
доступа к СУБД только с локального узла.

## 2. Порядок настройки

Сценарии собраны в каталоге `hosts/ksc-server/audit/` и выполняются от имени
администратора в указанном порядке.

| Шаг | Сценарий | Действие |
|-----|----------|----------|
| 1 | `00_Set-OsAudit.ps1` | Расширенная политика аудита ОС (40 подкатегорий, задаются по GUID), командная строка в событиях 4688, журналирование PowerShell с транскрипцией, включение и размеры каналов, SACL на каталоги и ветку реестра KasperskyLab |
| 2 | `10_Enable-DbAudit.ps1` | Включает плагин `server_audit`, создаёт каталог аудита с ограниченными правами, вносит блок параметров в `my.ini`, перезапускает службу и проверяет значения переменных |
| 3 | `20_Install-AuditForwarder.ps1` | Создаёт журнал «MariaDB-Audit», размещает конвертер в `C:\ProgramData\KscDeployment\bin`, регистрирует задачу `KSC-DbAudit-Forwarder` |
| 4 | `30_Set-KscAppAudit.ps1` | Журналы ПО Kaspersky (включение, размер, доступ УЗ сбора), SACL на каталог установки и KLSHARE, чек-лист параметров консоли (экспорт в SIEM, сроки хранения, роль аудитора) |
| 5 | `40_Set-AuditCollectorAccess.ps1` | Создаёт УЗ `kscaudit`, включает её в группы доступа, выдаёт права на журнал и WMI, открывает порты только для адреса коллектора |
| 6 | `12_Set-Mp10MariaDbAccess.ps1` | Настраивает отдельную read-only УЗ MariaDB и удалённый доступ для профиля MaxPatrol VM `MySQL Audit` |
| 7 | `90_Test-Audit.ps1` | Проверяет аудит ОС, СУБД, ПО и доставку событий, выводит таблицу результатов |

Откат: `10_Enable-DbAudit.ps1 -Rollback`, `20_Install-AuditForwarder.ps1 -Rollback`,
`40_Set-AuditCollectorAccess.ps1 -Rollback`. Изменяющие сценарии `00_`, `10_`,
`12_`, `20_`, `30_` и `40_` поддерживают `-WhatIf`; перед применением выполните их
в этом режиме. Сценарии `21_` и `90_` являются конвертером и проверкой и не
имеют режима предварительного просмотра изменений.

Сценарий `12_Set-Mp10MariaDbAccess.ps1` относится к отдельному аудиту
MaxPatrol VM по профилю `MySQL Audit` и не заменяет передачу событий
`MariaDB-Audit` в SIEM.

Параметры решения сосредоточены в `common/config.ps1`, секции «Аудит ОС
и прикладного ПО» и «Аудит СУБД»: адреса узла и коллектора, имя учётной записи,
каталоги и ротация, состав событий, размеры журналов, период запуска конвертера.

Узел в домене: состав аудита ОС следует закрепить в групповой политике, иначе
локальные значения будут перезаписаны при очередном обновлении политики.

## 3. Соответствие перечню событий

### 3.0. Операционная система

| Требование перечня (ОС) | Подкатегория аудита | Коды событий |
|--------------------------|----------------------|---------------|
| Вход в систему и завершение сеанса, в том числе неуспешный | Вход, Выход, Особый вход, Прочие события входа/выхода | 4624, 4625, 4634, 4647, 4648, 4672, 4778, 4779 |
| Использование незарегистрированных УЗ, блокировка | Проверка учётных данных, Блокировка УЗ, Kerberos | 4625, 4740, 4768, 4771, 4776 |
| Создание, изменение, удаление УЗ и групп | Управление УЗ и группами | 4720-4726, 4728-4735, 4738, 4767, 4781 |
| Изменение полномочий и политик | Изменение политики аудита/авторизации, Особые права | 4670, 4672, 4673, 4719, 4904, 4906, 4907 |
| Действия администраторов (расширение) | Создание процесса с командной строкой, журналирование PowerShell | 4688, 4689; PowerShell/Operational 4103, 4104 |
| Доступ к защищаемым объектам (расширение) | Файловая система и реестр по SACL, Общие папки, Съёмные носители | 4656, 4660, 4663, 4670, 5140, 5145 |
| Отказ средств защиты, целостность | Целостность системы, Изменение состояния безопасности | 1102, 4608, 4609, 4616, 4697, 5038 |

Подкатегории задаются по GUID: названия локализованы, и вызов `auditpol`
с английским именем на русской сборке Windows завершается ошибкой.

### 3.1. СУБД

| Требование перечня (СУБД) | Реализация | Код события в журнале |
|---------------------------|------------|-----------------------|
| Успешная авторизация, начало и завершение сессии | `server_audit_events=CONNECT` | 1001 (подключение), 1002 (отключение) |
| Неуспешная авторизация, попытка использования незарегистрированной УЗ | запись `CONNECT` с ненулевым кодом возврата | 1003 |
| Действия администраторов: `SELECT`, `INSERT`, `UPDATE`, `DELETE`, `CALL`, `LOCK` | `server_audit_events=QUERY` | 1010, 1012 |
| Действия администраторов: `CREATE`, `ALTER`, `DROP`, `TRUNCATE`, `RENAME` | `QUERY` (класс DDL) | 1011 |
| Назначение и отзыв полномочий: `GRANT`, `REVOKE` | `QUERY` (класс DCL) | 1013 |
| Объекты, затронутые командой | `server_audit_events=TABLE` | 1020 |
| Контроль работоспособности источника | служебная запись конвертера | 1100 |
| Отказ подсистемы регистрации | ошибка конвертера | 1101 |

Состав полей записи события (требование о содержании записи):

| Поле перечня | Поле события |
|--------------|--------------|
| дата и время события | `event_time` |
| наименование инициировавшей УЗ | `db_user` |
| IP-адрес узла | `db_host`, `server_host` |
| IP-адрес источника | `src_host` |
| наименование устройства | имя компьютера-источника события |
| описание события | `operation`, `database`, `object`, `return_code`, `raw` |

Поле `raw` содержит исходную строку плагина: она используется при разборе
инцидентов и как подтверждение неизменности переданных данных.

### 3.2. Исключение служебной учётной записи

Параметр `AuditExclUsers` по умолчанию исключает из регистрации `QUERY`/`TABLE`
учётную запись Сервера администрирования `kscadmin`: она выполняет непрерывный
поток технических запросов объёмом в сотни ГБ в сутки, что выводит из строя
цепочку доставки. События подключения и отключения этой УЗ регистрируются
всегда.

Если методика аттестации требует регистрации действий **всех без исключения**
учётных записей, задайте `AuditExclUsers = ''` и заранее оцените объём хранения
и пропускную способность коллектора.

### 3.3. Прикладное ПО (KSC)

| Требование перечня (ПО) | Реализация |
|-------------------------|------------|
| Вход в консоль управления СЗИ, успешный и неуспешный | события категории «Аудит» Сервера администрирования, экспорт в SIEM |
| Изменение политик, задач, прав, лицензии | события «Изменён объект», «Изменено состояние объекта» |
| Срабатывания средств защиты на устройствах | события защиты от Агентов, экспорт в SIEM |
| Отказ и останов средства защиты | события служб Kaspersky в журналах Windows (System, Kaspersky Event Log) |
| Изменение файлов и параметров СЗИ (расширение) | SACL на каталог установки, KLSHARE, резервные копии и ветку реестра KasperskyLab — события 4663, 4670, 4657 |

События Сервера администрирования хранятся в собственной базе и передаются
в MaxPatrol двумя способами: экспортом по Syslog/CEF (основной) и записью в
журнал Windows с последующим чтением коллектором (резервный, включается
в политике Агента и KES).

## 4. Настройка источника в MaxPatrol 10

1. В разделе учётных записей MaxPatrol создайте учётную запись типа
   «логин-пароль»: `KSC\kscaudit` (локальная УЗ узла СУБД), пароль — заданный
   на шаге 3 порядка настройки.
2. Убедитесь, что актив `10.20.30.75` заведён в системе.
3. В задаче сбора событий Windows укажите:
   - транспорт: сбор журналов событий Windows (RPC/WMI);
   - узел: `10.20.30.75`;
   - учётная запись: созданная на шаге 1;
   - журналы: `Security`, `System`, `Application`, `MariaDB-Audit`,
     `Microsoft-Windows-PowerShell/Operational`, `Kaspersky Event Log`
     (последний — после включения записи событий ПО в журнал Windows).
   Для событий Сервера администрирования дополнительно заведите источник
   Syslog (формат CEF, порт 514) и включите экспорт в свойствах Сервера.
4. Запустите задачу и убедитесь в поступлении событий с источником
   `MariaDB-ServerAudit`.
5. Настройте контроль поступления: отсутствие события с кодом 1100 более
   45 минут означает отказ подсистемы регистрации; событие 1101 —
   ошибку конвертера.

Сетевой доступ: коллектору открыты только TCP 135 и динамический диапазон
RPC 49152-65535 с адреса `10.20.30.73`. Адрес коллектора следует также внести
в `SecurityToolsHosts` (`common/config.ps1`) и перезапустить
`10_Set-Firewall.ps1`, чтобы правила управления узлом не расходились.

## 5. Эксплуатация

- **Хранение.** Файл аудита и журнал Windows — локальные буферы (около 2 ГБ и
  1 ГБ соответственно, перезапись по мере заполнения). Хранение событий в
  течение установленного срока обеспечивает коллектор.
- **Ежедневно.** Проверять поступление событий 1100 и отсутствие событий 1101.
- **Еженедельно.** Выполнять `90_Test-Audit.ps1`, результат прикладывать к
  журналу контрольных мероприятий.
- **При изменении конфигурации СУБД.** Блок параметров аудита в `my.ini`
  ограничен маркерами `KSC-AUDIT BEGIN` / `KSC-AUDIT END` и управляется
  сценарием; ручные правки внутри блока будут перезаписаны.
- **Пароль УЗ `kscaudit`.** Хранится в парольном хранилище, в файлах
  репозитория не размещается. При смене пароля обновите учётную запись
  в MaxPatrol.
