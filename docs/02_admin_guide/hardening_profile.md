# Расширенный профиль защищённости узлов

Приложение к руководству администратора. Описывает состав расширенного
(строгого) профиля, применяемого к узлам системы, порядок его ввода в
действие и отката.

Профиль рассчитан на системы ограниченного доступа в изолированном
аттестованном контуре: обращения к внешним сетям отсутствуют, управление
выполняется только с АРМ администратора `10.20.30.15`.

---

## 1. Профили и порядок выбора

| Профиль | Назначение | Запуск |
|---|---|---|
| `Strict` | Расширенный профиль, применяется по умолчанию ко всем узлам | `.\Invoke-Hardening.ps1` / `sudo ./harden.sh --apply` |
| `Baseline` | Прежний базовый набор мер; применяется, если расширенный профиль нарушает работу прикладного ПО и требуется время на разбор | `.\Invoke-Hardening.ps1 -Level Baseline` / `sudo ./harden.sh --apply --level baseline` |

Порядок ввода расширенного профиля обязателен и одинаков для всех типов узлов:

1. Предварительный просмотр без изменений: `-WhatIf` (Windows), `--check` (Debian).
2. Применение на одном узле каждого типа.
3. Проверка работоспособности: вход пользователя, работа прикладного ПО,
   связь Агента с Сервером, обновление баз, доступ администратора.
4. Применение на остальных узлах.

Отступление от порядка приводит к одновременной потере управления
несколькими узлами: часть мер профиля (назначение прав, ограничение
интерпретаторов, управление запуском программ) отсекает и нарушителя,
и администратора.

## 2. Состав профиля: узлы Windows

Меры реализованы функциями модуля `common/WindowsBaseline.psm1` и
вызываются сценариями `hosts/*/hardening/Invoke-Hardening.ps1`.

| Область | Мера | Функция |
|---|---|---|
| Устаревшие протоколы | Отключение SMBv1, LLMNR, WPAD, NetBIOS over TCP/IP; обязательная подпись SMB | `Disable-LegacyProtocols` |
| Криптографические протоколы | Отключение SSL 2.0/3.0, TLS 1.0/1.1, слабых шифров и хеш-функций; TLS 1.2 | `Set-TlsHardening` |
| Проверка подлинности | Только NTLMv2, запрет LM и NTLMv1, запрет хранения WDigest, ограничение удалённого доступа к базе учётных записей | `Set-AuthenticationHardening` |
| Пароли и блокировка | Локальные учётные записи: длина от 14 символов (16 на АРМ), сложность, история 24, срок 60 суток (45 на АРМ), блокировка после 5 попыток (3 на АРМ) | `Set-PasswordPolicy` |
| Назначение прав | Локальным учётным записям запрещён сетевой и удалённый интерактивный вход; отладка программ — только администраторам; изъяты права создания маркера и работы в качестве части операционной системы | `Set-UserRightsHardening` |
| Учётные данные | Защита процесса LSA (`RunAsPPL`), Credential Guard, запрет сохранения доменных учётных данных, ограничение делегирования | `Set-CredentialProtection` |
| Сетевой стек | Запрет маршрутизации от источника и перенаправлений ICMP, отключение туннелей IPv6 (Teredo, 6to4, ISATAP, IP-HTTPS), запрет гостевого доступа SMB, обязательные подпись и шифрование защищённого канала с контроллером домена, запрет обычной проверки подлинности WinRM | `Set-NetworkStackHardening` |
| Интерпретаторы | Отключение PowerShell 2.0 (не ведёт журнал блоков сценариев) и сервера сценариев Windows | `Set-ScriptHostHardening` |
| PowerShell | Журнал блоков сценариев и модулей, стенограммы, политика запуска `AllSigned` (`RemoteSigned` на Сервере до внедрения подписи), режим ограниченного языка на рабочих станциях | `Set-PowerShellHardening` |
| Средство защиты | Правила сокращения поверхности атаки, защита сети, контролируемый доступ к папкам, защита от нежелательного ПО | `Set-DefenderStrict` |
| Съёмные носители | Запрет записи (рабочие станции, Сервер) либо полный запрет (АРМ администратора) | `Set-RemovableStorageHardening` |
| Запуск программ | Политика AppLocker для исполняемых файлов, сценариев и установочных пакетов | `Set-AppLockerBaseline` |
| Обновления | Автоматическая перезагрузка запрещена, установка — по решению администратора, доставка обновлений между узлами по сети отключена | `Set-UpdateHardening` |
| Диагностические сведения | Передача телеметрии, отчётов об ошибках и удалённый помощник отключены | `Set-TelemetryHardening` |
| Предупреждение при входе | Текст о принадлежности системы и регистрации действий | `Set-LegalNotice` |
| Регистрация событий | Расширенный набор подкатегорий аудита, включая проверку учётных данных, операции Kerberos, изменение прав, работу с носителями и общими ресурсами | `Set-AuditPolicy -Strict` |
| Службы | Отключение неиспользуемых служб, включая службы удалённого доступа и диагностики, с перечнем исключений по роли узла | `Disable-UnneededServices -Strict` |

### 2.1. Различия по типам узлов

| Узел | Отличия |
|---|---|
| Сервер администрирования KSC | Сохраняются службы удалённого реестра (задачи удалённой установки Агентов), удалённых рабочих столов и удалённого управления: узел администрируется с АРМ. PowerShell — `RemoteSigned`: в режиме `AllSigned` не выполняются неподписанные сценарии обслуживания. Съёмные носители — запрет записи |
| АРМ администратора (RDS) | Кеширование доменных входов запрещено полностью. Перенаправление в сеансах запрещено целиком. Делегирование ограничено режимами Restricted Admin и Remote Credential Guard. Съёмные носители запрещены полностью. PowerShell — `AllSigned`. Пароли и блокировка строже, чем на прочих узлах |
| Рабочая станция Windows | RDP отключён (включается `-AllowRdp` с ограничением источника). Доступ к SMB и RPC закрыт, если не задан `-AllowRemoteDeploy`. PowerShell — режим ограниченного языка |
| Контроллер домена | Отдельный сценарий `hosts/dc-gpo/hardening/Invoke-Hardening.ps1` работает в режиме проверки. Подпись LDAP, привязка канала LDAP, ограничения NTLM и типы шифрования Kerberos **не изменяются автоматически**: эти параметры нарушают работу клиентов, узлов Debian и части средств защиты. Решение принимается после проверки совместимости на резервном узле |

## 3. Состав профиля: узлы Debian

Реализовано в `hosts/linux-debian/hardening/harden.sh`.

| Область | Мера |
|---|---|
| SSH | Вход только по ключам, без root; наборы алгоритмов без устаревших примитивов; запрет проброса портов, агента, туннелей и переменных окружения; предупреждение при входе |
| Источник подключений SSH | Ограничивается правилом ufw (только с АРМ). Блок `Match Address` задаёт условия сеанса и сам по себе не запрещает прочие адреса: при обходе межсетевого экрана вход с ключом остаётся возможен. При учтённом перечне администраторов добавьте `AllowUsers`/`AllowGroups` вручную |
| Межсетевой экран | Запрет входящих по умолчанию; SSH — только с АРМ; служебные порты Агента — только с Сервера |
| Параметры ядра | Защита сетевого стека, `kernel.yama.ptrace_scope`, запрет `kexec` и непривилегированного BPF, ограничение доступа к сведениям ядра |
| Пароли | Срок действия 90 суток, сложность не менее 14 символов и 4 классов символов (`pam_pwquality`), `SHA512`, `umask 027` |
| Модули ядра | Запрет загрузки неиспользуемых модулей: устаревшие файловые системы, `usb-storage`, `firewire`, `bluetooth`, редкие сетевые протоколы |
| Файловые системы | Параметры `nodev`, `nosuid`, `noexec` **проверяются, но не изменяются**: изменение `/etc/fstab` выполняется вручную после проверки совместимости с KESL и установщиками пакетов |
| Аудит | Правила auditd на изменение учётных записей, средств защиты, планировщика, модулей ядра и работу с привилегиями; блокировка правил от изменения до перезагрузки |
| Журналы | Постоянное хранение системного журнала, до 1 ГБ, 90 суток на узле; долговременное хранение — на Сервере администрирования |
| Планировщик | Задания cron и at разрешены только суперпользователю; прежние списки `cron.allow`, `at.allow`, `cron.deny`, `at.deny` сохраняются с суффиксом `.ksc-bak-<дата>` — служебные учётные записи возвращаются в `cron.allow` вручную |
| Дампы памяти | Сохранение дампов запрещено |
| Обновления | Автоматическое обновление из внешних источников отключено |

## 4. Меры, требующие отдельного решения

Перечисленные меры включены в профиль, но по умолчанию действуют в режиме
наблюдения либо не применяются автоматически. Причина одна: в режиме
блокировки они прерывают работу прикладного ПО, а восстановление требует
доступа к узлу, который сама мера и ограничивает.

| Мера | Состояние по умолчанию | Условие перехода к блокировке |
|---|---|---|
| Правила сокращения поверхности атаки Defender | Режим наблюдения | Разбор событий 1121/1122 за 2–4 недели, затем `Set-DefenderStrict -Enforce` |
| Защита сети и контролируемый доступ к папкам | Режим наблюдения | То же |
| AppLocker | Режим наблюдения | Разбор журнала AppLocker, внесение согласованных расположений в `-AllowedPaths`, затем `-EnforceAppLocker`. Каждое расположение из `-AllowedPaths` разрешает запуск всем пользователям по пути: до включения блокировки проверьте `icacls`, что в нём и во вложенных каталогах нет права записи у обычных пользователей |
| Credential Guard | Параметры записываются | Поддержка вложенной виртуализации на гипервизоре и загрузка в режиме UEFI с безопасной загрузкой |
| Подпись LDAP, привязка канала LDAP, ограничения NTLM, типы шифрования Kerberos | Только проверка | Проверка совместимости клиентов, узлов Debian и смежных средств защиты |
| `noexec`, `nosuid`, `nodev` на разделах Debian | Только проверка | Проверка работы KESL и установщиков пакетов |
| Политика запуска PowerShell `AllSigned` | Применяется на АРМ и рабочих станциях | Внедрение подписи сценариев корпоративным сертификатом; до этого — `RemoteSigned` |

## 5. Откат

| Что изменялось | Как вернуть |
|---|---|
| Параметры реестра Windows | `common\Restore-Baseline.ps1 -RollbackFile C:\ProgramData\KscDeployment\rollback\rollback-<дата>.json` |
| Локальная политика безопасности Windows (пароли, назначение прав) | `secedit /configure /db secedit.sdb /cfg C:\ProgramData\KscDeployment\rollback\secpol-<дата>.inf /overwrite` |
| Политика AppLocker | Применить сохранённый файл: `Set-AppLockerPolicy -XmlPolicy C:\ProgramData\KscDeployment\rollback\applocker-before-<дата>.xml` |
| Списки cron и at на Debian | Восстановить `cron.allow`, `at.allow` из `.ksc-bak-<дата>`; если копий нет, файлов до применения не было — удалите их |
| Правила сокращения поверхности атаки | `Remove-MpPreference -AttackSurfaceReductionRules_Ids <идентификатор>` |
| Отключённые службы | Восстанавливаются вручную: перечень изменений выведен в отчёте сценария |
| Файлы конфигурации Debian | Исходные файлы сохранены рядом с суффиксом `.ksc-bak-<дата>` |

Файлы отката содержат прежнее состояние узла и подлежат хранению до
подтверждения работоспособности после применения профиля.

## 6. Проверка после применения

Windows:

```powershell
.\hardening\Invoke-Hardening.ps1 -WhatIf     # расхождения с профилем
auditpol /get /category:*                    # действующая политика аудита
Get-MpPreference | Select-Object AttackSurfaceReductionRules_Ids, AttackSurfaceReductionRules_Actions
Get-AppLockerPolicy -Effective -Xml
```

Debian:

```bash
sudo ./hardening/harden.sh --check
sudo sshd -t
sudo auditctl -l
sudo ufw status verbose
```

Проверка сохранения работоспособности системы защиты обязательна:
Сервер администрирования — `hosts/ksc-server/60_Test-Deployment.ps1`,
узлы Debian — `hosts/linux-debian/30_test-agent.sh`, охват узлов —
`hosts/dc-gpo/20_Test-AgentDeployment.ps1`.

## 7. Состояние проверки

Сценарии прошли статическую проверку синтаксиса (разбор PowerShell,
PSScriptAnalyzer, `bash -n`). Выполнение на Windows Server 2022 и на узлах
Debian с KESL не проводилось: применяйте профиль сначала в режиме
предварительного просмотра и на одном узле каждого типа.
