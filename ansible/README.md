# Ansible (заготовка, в текущем развёртывании не используется)

Каталог создан на перспективу. **Сейчас средства управления конфигурацией
не применяются**: установка выполняется по мере необходимости вручную,
адресация статическая, перечень узлов ведётся вручную — это осознанное
решение для аттестованного контура, где каждое изменение состояния узла
должно быть согласовано и зафиксировано.

Роли ниже описывают те же действия, что и сценарии в `hosts/`, и служат
основой, если в дальнейшем будет принято решение о переходе к
автоматизированному управлению конфигурацией.

## Что потребуется до применения

| Условие | Причина |
|---|---|
| Согласование с администратором безопасности | Появляется новый канал управления узлами — он должен быть учтён в модели угроз и в схеме информационных потоков |
| Выделенный узел управления | Управляющий узел должен находиться в том же контуре и иметь ограниченный доступ (по аналогии с АРМ администратора) |
| SSH по ключам, без пароля root | Профиль харденинга Debian уже это требует |
| Локальное зеркало пакетов | Внешние репозитории в контуре недоступны |
| Хранилище секретов (ansible-vault) | Пароли не должны храниться в открытом виде в репозитории |

## Структура

```
ansible/
├── inventory/
│   └── hosts.yml.example     перечень узлов (заполняется вручную)
├── group_vars/
│   └── all.yml.example       параметры Сервера KSC и портов
├── roles/
│   ├── klnagent/             Агент администрирования
│   ├── kesl/                 Kaspersky Endpoint Security для Linux
│   └── debian_hardening/     базовый профиль защищённости
└── site.yml.example          сценарий верхнего уровня
```

Файлы с суффиксом `.example` намеренно не являются рабочими: они не будут
случайно применены и требуют осознанного переименования.
